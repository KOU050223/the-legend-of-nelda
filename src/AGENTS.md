# フロントエンドガイドライン

## テスト

書き方・実行方法は [`docs/testing-guide.md`](../docs/testing-guide.md) を参照する。

### テスト名は「保証したい動作」を書く

`it` の名前には、**実装を差し替えても真であり続ける文**を書く。

判定基準は次の1つ。

> **store を別のものに替えたら / 関数名を変えたら名前が嘘になるなら、
> それは実装の名前になっている。**

ライブラリ名・内部関数名・変数名・「〜が呼ばれる」はテスト名に入れない。
入れてよいのはドメインの言葉（`SLEEPINESS` / `MISS` / `PlayerAction` など）。

```ts
// NG: 実装の名前。Zustand をやめた時点で嘘になる
it('storeのSLEEPINESSを表示する');
it('setSleepinessが呼ばれる');
it('judgePlayerActionがMISSを返す');

// OK: 保証したい動作。実装を替えても成り立つ
it('SLEEPINESSの値を表示する');
it('入力がまだ無い場合はREADYを表示する');
it('受付内でも不正解の入力はHITになる');
```

条件がある場合は「**〜なら、〜になる**」の形にすると、
名前だけで仕様が読める。

### describe は対象、it は動作

`describe` にはテスト対象そのものを書く。ここは実装名でよい。
**動作を書くのは `it` 側**で、この役割分担は変えない。

```ts
// describe = 対象なので実装名でよい
describe('judgePlayerAction', () => {
  // it = 動作なので実装名を書かない
  it('受付内でも不正解の入力はHITになる', () => {});
});
```
