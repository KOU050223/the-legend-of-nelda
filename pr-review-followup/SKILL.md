# pr-review-followup

PRのレビュー指摘を「修正してコミットしただけ」で終わらせない。各指摘について、レビュアーが変更内容と検証結果を追える状態にし、解決可能な会話は解決済みにする。

## 使うとき

レビューコメントへのコード・設定・テストの修正を完了した後、PR上の該当スレッドへ返答して解決する必要があるときに使う。レビュー本文を読んで対応方針を決める工程だけには使わない。

## Instructions

1. 対応したPRと、修正の根拠になるレビュー会話を特定する。別のPRや古いレビューのスレッドに返信しない。
2. 各指摘が実際に解消済みか確認する。未解決、意図的に見送った、または追加判断が必要な指摘には、解決済みとして扱わない。
3. 解消済みの各スレッドに、そのスレッドへの返信として対応内容を簡潔に書く。変更した箇所・方針と、実行した関連テストまたは未実施理由を含める。単なる「対応しました」だけの返信にはしない。
4. 返信がPR上に投稿されたことを確認してから、プラットフォームで会話を解決できる場合はそのスレッドを解決する。返信できない、または解決状態を確認できない場合は、完了と主張せず原因を報告する。
5. 複数の独立した指摘は、それぞれの元スレッドへ返信・解決する。関連する補足返信を一つにまとめるのはよいが、別スレッドの指摘を一つのコメントで済ませない。

返信例:

> `PlayerHealth` の初期値を生成元で固定するよう変更し、再生成時にも値が引き継がれない問題を解消しました。`npm test -- PlayerHealth` を実行済みです。

コメント投稿や会話の解決は外部状態を変更する操作である。リポジトリの運用ルール、権限、ユーザーから与えられた操作範囲に従うこと。投稿・解決まで済んだスレッド、残件、実行した検証を最終報告で区別して示す。
